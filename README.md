[![Playwright](https://img.shields.io/badge/Playwright-1.55-2EAD33?logo=playwright&logoColor=white)](https://playwright.dev/)

Исследовательская система сбора и нормализации цен из онлайн-каталогов
«Пятёрочки» и «Магнита». Проект развивается для дипломной работы по экономике
НИУ ВШЭ, 4 курс.

> Использование разрешено только для некоммерческих дипломных работ, научных
> статей и академических исследований. Коммерческое использование запрещено.
> Это **не open-source лицензия**. Условия: [LICENSE](LICENSE).

## Что умеет проект

- независимые сборщики двух сетей на TypeScript + Playwright;
- запросы из контекста страницы и отдельный профиль каждой сети;
- полная пагинация, паузы, журналирование и осторожные повторы;
- неизменяемые исходные ответы в `data/raw/`;
- единая модель товаров и цен в целых копейках;
- последовательные очереди, checkpoint, resume и повтор ошибок;
- отдельная подсистема обнаружения магазинов;
- терминальное меню с предварительным просмотром и подтверждением запуска;
- проверка качества и повторная нормализация без обращения к сайтам;
- подготовленный daily runner без автоматически включённого расписания.

PostgreSQL пока не подключена. JSON сохраняются локально и могут быть
импортированы в базу позднее.

## Архитектура

```text
store discovery ──→ справочники магазинов
                           │
                           ▼
scheduler ──→ collector ──→ raw JSON ──→ normalizer ──→ normalized JSON
                                │                              │
                                └──────── quality checks ─────┘
                                                               │
                                                       PostgreSQL (позже)
```

```text
src/
├── browser/           Playwright-клиенты
├── collectors/        сетевые сборщики
├── config/            аргументы и списки кодов
├── core/              общие типы, время, журнал и retry
├── normalizers/       единая модель товаров
├── operations/        ежедневный последовательный запуск
├── quality/           проверка локальных данных
├── reprocessing/      повторная обработка raw JSON
├── scheduler/         очереди и состояния
├── store-discovery/   отдельный поиск магазинов
└── terminal/          текстовый интерфейс
```

Сетевой код не зависит от PostgreSQL. Исходные JSON не удаляются при
нормализации. Модули и браузерные профили сетей независимы.

## Быстрый старт

Требования: Windows, Node.js и pnpm.

```powershell
pnpm install
pnpm exec playwright install chromium
pnpm run menu
```

Меню показывает число магазинов, категорий и заданий и требует явного `ДА`.
Массовый сбор по умолчанию не запускается.

### Основные команды

```powershell
# Одна пара магазин × категория
pnpm run collect:pyaterochka -- --store 324K --category 251C12891 --headless
pnpm run collect:magnit -- --store 780019 --category 64247 --headless

# Операции без сети
pnpm run quality
pnpm run reprocess -- --raw "data/raw/ДАТА/СЕТЬ/КАТАЛОГ"
pnpm run daily -- --config config/daily.json --dry-run

# Проверка кода
pnpm run lint
pnpm run typecheck
pnpm run test
pnpm run build
```

Перед сбором подготовьте отдельный профиль сети. Не используйте основной
профиль Chrome и не запускайте два процесса с одним профилем одновременно.

## Данные

```text
data/
├── raw/YYYY-MM-DD/          исходные ответы и метаданные
├── normalized/YYYY-MM-DD/   единые снимки товаров
├── state/                   прогресс очередей
└── reports/                 локальные отчёты качества
```

Для записи хранятся сеть, магазин, категория, товар, логическая дата запуска
и точное время получения. Деньги представлены как
`{ amountMinor, currency: "RUB", minorUnitScale: 2 }`.

Raw-файлы, профили, журналы, `.env`, реальные списки кодов и база исключены
из Git. JSON в `samples/` нужны для воспроизводимых тестов нормализации.

## Обнаружение магазинов

Это отдельная, редко запускаемая операция, а не часть ежедневного сбора цен.

```powershell
pnpm run discover:stores -- --chain magnit --city "Санкт-Петербург" --query "санкт-петербург,"
```

Для «Магнита» эталонный список `/search` объединяется с несколькими проходами
нестабильной пагинации `/search/detail`. Для «Пятёрочки» проверяются пробные
координаты доставки и результаты объединяются по `sap_code`. Сохраняются raw,
checkpoint, `stores.json`, `stores.csv` и `store-codes.txt`.

Готовый запуск проверяется и публикуется в локальный нормализованный справочник
отдельной командой:

```powershell
pnpm run publish:stores -- --run "data/raw/YYYY-MM-DD/magnit/store-discovery/имя-запуска"
```

Публикация добавляет отчёт качества и готовую группировку кодов и адресов по
административным и муниципальным районам. Исходные ответы не изменяются.

Подробнее: [RUN_STORE_DISCOVERY.md](docs/RUN_STORE_DISCOVERY.md).

## Ограничения

- параллельность сейчас равна 1;
- 401/403/429 и `Retry-After` останавливают очередь;
- CAPTCHA и средства контроля доступа не обходятся;
- пропущенные исторические цены восстановить невозможно;
- акции «по карте» и весовые товары требуют осторожной интерпретации;
- сборщик не доказывает совпадение онлайн-цены с физическим ценником.

Проект не предоставляет разрешения нарушать закон, условия сайтов, права на
базы данных или ограничения доступа. Пользователь отвечает за законность
конкретного исследования, частоту запросов и публикацию данных.
