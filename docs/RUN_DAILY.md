# Подготовка ежедневного запуска

Расписание Windows автоматически НЕ установлено. Сначала нужно выбрать
магазины, категории и удобное время. Сервер PostgreSQL для запуска не нужен.

## Конфигурация

Создайте `config/daily.json` на основе `config/daily.example.json`.
Для каждой выбранной сети укажите файлы магазинов и категорий. Пути считаются
от корня проекта. Сети выполняются строго в порядке jobs, по одной.
Часовой пояс задаётся явно (`Europe/Moscow`) и передаётся дочерним сборщикам.
Пример конфигурации не запускается без заполненных локальных файлов.

Проверка всех планов без запросов и записи состояния:

```powershell
pnpm run daily -- --config config/daily.json --dry-run
```

Если флаг режима не указан, тоже выполняется только предварительная проверка.
Для реального разового выполнения всего daily-плана нужен явный `--execute`:

```powershell
pnpm run daily -- --config config/daily.json --execute
```

Это может запустить много запросов: сначала проверьте число заданий и
подходящие форматы магазинов. Daily runner не фильтрует форматы Магнита.

## Защита от повторов

- Сначала проверяются файлы всех сетей; при ошибке не стартует ни одна.
- Сети не работают параллельно; при ненулевом коде первой вторая не запускается.
- В `data/state/daily/active.lock` фиксируется активный процесс.
- В `data/state/daily/YYYY-MM-DD.json` сохраняется итог. Повторный execute
  в ту же логическую дату пропускается даже после неудачной попытки.
- Пропущенные даты не воспроизводятся. Новый запуск получает текущую дату.
- Прерывание оставляет файлы состояния сетей для ручного resume/retry-failed.

Если процесс аварийно завершился, active.lock может остаться. Он специально
не удаляется автоматически: сначала проверьте, что daily и дочерний сборщик
не работают. Только после этого можно убрать конкретный устаревший lock.
PID записан внутри него. Не удаляйте дневной отчёт для обхода защиты от
повторов; продолжите нужную очередь через меню или команды resume.

Блокировка daily не заменяет блокировку профилей Chrome. Не запускайте
отдельно discovery или ручной сбор той же сети во время daily.

## Настройка Windows — позднее, после подтверждения времени

Рекомендуемый начальный режим: один раз в день, последовательный обход
выбранных сетей. Никакого специального времени обновления цен не предполагается.

В Планировщике заданий Windows понадобится действие запуска Node:

- Программа: полный путь к установленному `node.exe` (узнать через
  `node -p process.execPath`).
- Аргументы: `--import tsx "D:\coding\projects\retail-collector-starter\src\daily.ts" --config "D:\coding\projects\retail-collector-starter\config\daily.json" --execute`.
- Рабочая папка: `D:\coding\projects\retail-collector-starter`.

Используйте того же пользователя Windows, который подготовил браузерные
профили. Для начала — запуск при входе этого пользователя в систему, без
хранения его пароля в проекте. При настройке выберите запрет параллельного
экземпляра и возможность запуска после пропущенного времени. Проверьте
локальный часовой пояс Windows: час триггера и timeZone данных — разные вещи.

На выключенном ноутбуке сбор не работает. Задание не меняет настройки сна,
не управляет VPN, не пробуждает и не выключает компьютер самостоятельно.
Итоги смотрите в data/state/daily, подробности — в состояниях сетей и logs.

Пока в проекте подготовлен и проверен разовый daily runner; фактическая
регистрация и проверка запуска из Windows Scheduler ещё предстоят.
