# Контекст проекта

## Предметная область

Дипломный проект связан со сбором и анализом данных о розничных ценах.
Основные источники:

- «Пятёрочка»;
- «Магнит».

Планируется сбор магазинов Москвы и Санкт-Петербурга.

## Что уже было сделано раньше

Существовали браузерные JavaScript-скрипты, которые вручную запускались
через DevTools.

### Пятёрочка

Скрипт:

- принимал список кодов магазинов;
- принимал список категорий;
- перебирал магазин × категория;
- проходил пагинацию;
- делал паузы;
- повторял запросы после ошибок;
- сохранял отдельный JSON на каждую пару магазин × категория.

Использовался endpoint вида:

```text
https://5d.5ka.ru/api/catalog/v2/stores/{store}/categories/{category}/products
```

### Магнит

Скрипт:

- принимал список `storeCode`;
- принимал список `categoryId`;
- отправлял POST-запросы;
- проходил пагинацию;
- делал паузы и повторы;
- сохранял отдельные JSON.

Использовался endpoint:

```text
https://magnit.ru/webgate/v2/goods/search
```

### Конвертер

Существовал Node.js-скрипт `json_to_excel_combined.js`, который:

- читал папки с JSON;
- определял сеть, магазин и категорию по имени файла;
- нормализовал данные;
- создавал Excel-файлы;
- создавал общий отчёт.

## Старая схема

```text
ручной запуск браузерного скрипта
→ много JSON в Downloads
→ ручное перемещение файлов
→ ручной запуск конвертера
→ Excel
```

## Целевая схема

```text
фоновая программа
→ автоматический браузерный сбор
→ исходные JSON
→ нормализация
→ PostgreSQL
→ отчёты и экспорт
```

## Условия работы

- На первом этапе программа будет запускаться на личном Windows-компьютере.
- Пользователь должен иметь возможность параллельно работать за компьютером.
- Используются отдельные браузерные профили.
- Позже сборщик может быть перенесён на отдельный домашний компьютер.
- Решение пользователя от 3 сентября 2026: PostgreSQL будет локальной,
  с резервными копиями на стороне пользователя. Подключение БД отложено;
  сбор и подготовка работают через локальные raw и normalized JSON.
- Если компьютер выключен, исторические данные за пропущенные дни восстановить нельзя.

## Требования к устойчивости

- После перезапуска программа продолжает незавершённый сбор.
- Ошибка одного магазина не останавливает остальные.
- Неудачные задачи можно повторить отдельно.
- Пятёрочка и Магнит имеют отдельные очереди.
- Параллельность ограничена и задаётся конфигурацией.
- Начальная рекомендуемая параллельность:
  - Пятёрочка: 2;
  - Магнит: 2.

## Требования к времени

Для каждой записи необходимо хранить:

- дату логического запуска;
- точное время получения;
- сеть;
- магазин;
- категорию;
- товар;
- цены;
- доступность.

Нельзя полагаться на неподтверждённое предположение, что цены обновляются
строго в 23:59. Время обновления должно быть исследовано отдельно.
