# Товарный сборщик Магнита

Работает без SQL, отдельно от одноразовой утилиты `store-discovery`.
По умолчанию запускается одна явно выбранная пара магазин × категория.
Пакетный режим включается только явным `--batch` с двумя файлами.

```powershell
pnpm run collect:magnit -- --store 780019 --category 64247 --headless
```

Для проверки выбранного кода по справочнику добавьте:

```powershell
pnpm run collect:magnit -- --store 780019 --category 64247 --headless --stores-file "путь/к/stores.json"
```

Поддерживаются discovery JSON (`externalCode`, `chain`, `active`), старый
конфигурационный JSON (`code`, `active`), массив строк и TXT с одним кодом
на строку. Ведущие нули сохраняются, повторы удаляются, неактивные записи
исключаются. Файл другой сети отклоняется. TXT не содержит сеть или формат
магазина, поэтому для проверки принадлежности предпочтительнее JSON.
Передача только `--stores-file` НЕ запускает сбор всех перечисленных магазинов.

## Последовательная очередь и восстановление

Сначала проверьте план **без браузера, сетевых запросов и записи состояния**:

```powershell
pnpm run collect:magnit -- --batch --stores-file "путь/к/stores.json" --categories-file "путь/к/categories.txt" --dry-run
```

Вывод содержит общее число пар магазин × категория и первые 10 заданий.
Для реального запуска уберите `--dry-run` и при необходимости добавьте
`--headless`. Список должен содержать выбранные и проверенные магазины:
не следует автоматически запускать все 669 записей разных форматов.
Фильтрации по формату или доставке пока нет.

Задания выполняются по одному с паузой 3 секунды между ними. И пакетный,
и одиночный запуск сохраняют состояние в `data/state/magnit/RUN.json`.
Точный путь печатается в журнале начала и окончания запуска.

```powershell
pnpm run collect:magnit -- --resume "data/state/magnit/RUN.json" --headless
pnpm run collect:magnit -- --retry-failed "data/state/magnit/RUN.json" --headless
```

`--resume` обрабатывает только pending и прерванные running;
`--retry-failed` — только failed, не затрагивая pending. Успешные задания
не повторяются. Файлы магазинов/категорий для восстановления не нужны:
план взят из состояния, переопределять его нельзя. Эти режимы несовместимы.
`--dry-run` можно использовать и с восстановлением для предварительной проверки.

При 401/403/429 или Retry-After очередь получает статус paused, оставшиеся
магазины не опрашиваются. После устранения причины повторите failed, затем
продолжите pending через resume. Ошибка конкретного задания без блокировки
не останавливает остальные. Ошибки записи состояния останавливают процесс.
Незавершённые очереди не считаются completed.

Состояние сохраняется через временный файл и переименование. Прерванная
категория начинается с первой страницы в новом raw-каталоге; прежние файлы
не удаляются. Счётчик attempts считает запуски категории, а не HTTP-повторы.
Логическая дата и часовой пояс исходного запуска сохраняются при resume,
но collectedAt всегда отражает реальное новое время получения данных.
Это НЕ восстановление исторической цены за пропущенный день.

## Браузер и ограничения

По умолчанию установленный Chrome запускается видимо с отдельным профилем
`profiles/magnit/`. `--headless` скрывает окно, `--browser-channel chromium`
выбирает установленный Playwright Chromium. Настройка через интерфейс сайта:

```powershell
pnpm run profile:magnit
```

Не запускайте discovery и товарный сборщик одновременно: они используют
один профиль Магнита. Основной профиль пользователя не используется.
VPN и системные настройки программа не изменяет, CAPTCHA не обходит.
HTTP 403/429 и ответы с Retry-After останавливают этот запуск; временные
сетевые ошибки и отдельные 5xx повторяются до трёх попыток с растущей паузой.
Таймаут товарного запроса — 30 секунд, пауза между страницами — 1,5–3,5 секунды.
Параллельных запросов нет. Максимум — 100 страниц на выбранную категорию.

## Сохранение

- `data/raw/YYYY-MM-DD/magnit/STORE_CATEGORY_TIMESTAMP/`: исходные страницы,
  время запросов, manifest; при ошибке — failure.json.
- `data/normalized/YYYY-MM-DD/magnit/STORE_CATEGORY_TIMESTAMP.json`: снимки
  товаров со ссылками на исходные страницы.
- `logs/YYYY-MM-DD/magnit.jsonl`: события и ошибки.

Цены хранятся в копейках. `price` — текущая цена, `promotion.oldPrice` —
прежняя. У весового товара это цена указанной порции (`shelfLabel`), а не
обязательно цена килограмма. `weighted.unitPrice` остаётся в raw.
Условия акций (включая «по карте») тоже остаются в raw: текущая цена не
должна трактоваться как безусловно доступная всем покупателям.

Несовпадение количества, повтор товара, неверный offset или пустая страница
с hasMore=true считаются ошибками. Сохранённые страницы не удаляются.
После сбоя повтор категории начинается с начала в новом каталоге.
Manifest подтверждает raw-сбор; успешную нормализацию отмечает событие
`magnit.task.completed`. Итог всей очереди указан в поле status события
`magnit.run.completed` и в файле состояния. При ошибке смотрите failure.json.

## Справочник не гарантирует товарный каталог

669 активных физических магазинов не означают 669 доступных онлайн-каталогов.
Есть офлайн-магазины и разные форматы. Запрос пока использует подтверждённые
`storeType: "1"`, `catalogType: "1"`; прочие форматы ещё не проверены.
Заголовки версии приложения взяты из старого рабочего запроса: если API
изменится, понадобится новая диагностика, а не обход защиты.
