# Локальная проверка качества

Запуск из корня проекта:

```powershell
node --import tsx src/quality.ts
```

Также доступны `pnpm run quality` и пункт **9** терминального меню.
Команда не открывает браузер, не делает сетевых запросов, не меняет SQL,
исходные JSON, состояния или настройки расписания.

## Что проверяется

- JSON-структура, число снимков и соответствие заявленному count.
- Пустые категории (предупреждение, а не автоматически ошибка).
- Идентификаторы, названия, принадлежность сети, boolean доступности.
- Дубликаты товаров внутри одного файла.
- Наличие цены, формат целых копеек RUB/scale 2, нулевая цена,
  цена со скидкой выше обычной.
- Timestamps, порядок времени, корректность логической даты.
- Наличие raw-ссылок и файлов внутри data/raw. Ссылки наружу не читаются.
- Падение количества более чем на 50% относительно предыдущего однозначного
  корректного файла той же сети, магазина и категории.
- Статусы запусков: failed, pending, running, повреждённые состояния.
- Список сохранённых failure.json товарных сборщиков.

Ошибки и предупреждения группируются по коду; для строк даются первые
10 номеров примеров (нумерация с 1). count — число срабатываний проверки,
не обязательно число уникальных проблемных товаров.

## Результат

Каждый запуск создаёт новый каталог `data/reports/quality-TIMESTAMP-ID/`:

- `report.json` — машинно-читаемые результаты;
- `report.md` — читаемая сводка.

Папка отчётов исключена из Git. Старые отчёты и исходные данные сохраняются.
Код выхода 1 означает ошибку проверки/чтения, ошибки данных, failed-задачи
или повреждённый файл состояния. Одни предупреждения дают код 0.
Оставшиеся pending/running отражаются отдельно, но сами по себе код 1 не дают.

## Ограничения интерпретации

Это диагностический отчёт, а не доказательство полноты и правильности цен.
Он не сравнивает цены с сайтом или физическими ценниками, не проверяет
содержимое raw против каждого нормализованного поля и не исправляет данные.

Проверяются стандартные папки data/normalized, data/raw, data/state внутри
проекта. Пользовательские RAW_DATA_DIR/NORMALIZED_DATA_DIR/STATE_DATA_DIR
в этой команде пока не поддержаны. Утилита store-discovery исключена из обхода.

Повторная нормализация одного запуска отмечается MULTIPLE_VERSIONS. Ни одна
версия автоматически не объявляется правильной; они исключаются из
последовательного сравнения количества. Сумма строк включает все версии,
поэтому не равна количеству уникальных наблюдений.

В пустом normalized-файле текущего формата нет идентификаторов магазина и
категории. EMPTY_CATEGORY будет показано, но такой файл нельзя надёжно
связать с историей только по снимкам. Нельзя считать отсутствие файлов
успешным сбором. Падение >50% — настраиваемое в будущем диагностическое
правило, сейчас фиксированный порог, а не доказательство сбоя.

failure.json может относиться к старой уже исправленной попытке: наличие
такого файла само по себе не означает, что актуальная очередь неуспешна.
