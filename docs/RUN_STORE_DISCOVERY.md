# Сбор кодов и адресов магазинов

Модуль `src/store-discovery/` обнаруживает магазины отдельно от товарных
сборщиков. Он не записывает данные в PostgreSQL и не меняет конфигурацию
сбора товаров.

## Где находится реализация

```text
src/store-discovery/
├── cli.ts                  отдельная точка запуска
├── core/                   хранение, экспорт, HTTP и районы
├── magnit/                 поиск и пагинация Магнита
└── pyaterochka/            точки, геокодирование и Пятёрочка

tests/store-discovery/      автоматические тесты
```

Команда `pnpm discover:stores` запускает `src/store-discovery/cli.ts`. Этот
процесс не следует смешивать с ежедневным сбором товаров: сначала формируется
справочник магазинов, затем его коды используются планировщиком товарных задач.

## Когда запускать

Есть два режима использования:

1. Первичная инициализация — перед первым массовым сбором товаров.
2. Обновление справочника — ориентировочно раз в полгода либо при массовых
   ошибках каталогов, открытии новых магазинов или изменении зон доставки.

Каждое обновление должно создавать новый снимок. Предыдущие результаты не
перезаписываются и не удаляются.

## Результаты

Каждый запуск создаёт каталог:

```text
data/raw/YYYY-MM-DD/{chain}/store-discovery/{city}_{timestamp}/
├── responses/          исходные ответы API и метаданные запросов
├── checkpoint.json     прогресс для продолжения после остановки
├── manifest.json       сводка запуска
├── stores.json         полные нормализованные карточки
├── stores.csv          таблица адресов и координат
└── store-codes.txt     один код магазина на строку
```

Файл `store-codes.txt` можно передать товарному сборщику. Исходные ответы не
удаляются. Cookies, токены и чувствительные заголовки в файлы не записываются.

## Магнит

Магнит перечисляет магазины через `search/detail` страницами по 50. Порядок
страниц нестабилен, поэтому `/search` используется как эталонный перечень
кодов, а подробные страницы объединяются несколькими проходами до полного
покрытия. Автоматический запуск 1 сентября 2026 года получил 669 уникальных
магазинов Санкт-Петербурга. Запятая важна, потому что без неё поиск может
включить одноимённые улицы других городов.

Запуск в видимом браузере:

```powershell
pnpm discover:stores -- --chain magnit --city "Санкт-Петербург" --query "санкт-петербург,"
```

Headless-запуск после подготовки отдельного профиля `profiles/magnit/`:

```powershell
pnpm discover:stores -- --chain magnit --city "Санкт-Петербург" --query "санкт-петербург," --headless
```

В справочник сохраняются все найденные форматы. Доставка, самовывоз и покупки
в магазине остаются независимыми признаками и не используются для удаления
физического магазина.

## Пятёрочка

Пятёрочка возвращает один доставляющий магазин для одной координаты. Ответ
содержит `sap_code` и точный `shop_address`. Одинаковые `sap_code` объединяются,
после чего адрес каждого уникального магазина геокодируется для получения его
координат и района.

### Запуск с подготовленными точками

Файл точек должен быть JSON-массивом:

```json
[
  { "id": "P1", "level": 1, "latitude": 59.851209, "longitude": 30.468115 },
  { "id": "P2", "level": 1, "latitude": 59.861209, "longitude": 30.478115 }
]
```

Команда:

```powershell
pnpm discover:stores -- --chain pyaterochka --city "Санкт-Петербург" --points "data/input/spb-points.json"
```

### Генерация точек из GeoJSON

Поддерживается `Polygon` или `MultiPolygon`, а также GeoJSON `Feature` с такой
геометрией. Для первичного прохода рекомендуется жилой полигон, а не полный
прямоугольник города.

Два прохода с шагом 1500 и 1000 метров:

```powershell
pnpm discover:stores -- --chain pyaterochka --city "Санкт-Петербург" --geometry "data/input/spb-residential.geojson" --spacing "1500,1000"
```

Для каждого шага CLI создаёт обычную и смещённую на половину шага сетку. Это
снижает риск пропустить небольшую зону доставки. После первого реального
запуска плотность следует выбирать по числу новых `sap_code`:

```text
1500 м → основной список
1000 м → контрольный проход
500 м  → только если продолжают появляться новые коды
```

Полноту Пятёрочки нельзя доказать одним запросом, поскольку API не выдаёт
общий список. Практический критерий — два последовательных прохода без новых
`sap_code`.

## Продолжение после остановки

Нужно повторить исходную команду с теми же городом, query, точками или
геометрией и добавить каталог незавершённого запуска:

```powershell
pnpm discover:stores -- ... --resume "data/raw/2026-09-01/magnit/store-discovery/имя-запуска"
```

Магнит продолжит со следующего `offset`. Пятёрочка продолжит со следующей
необработанной точки. Геокодирование небольшого списка уже найденных магазинов
после аварийной остановки может безопасно повториться.

## Обновление существующего справочника

После повторного обнаружения новый снимок необходимо сравнить с последним
подтверждённым справочником:

- `new` — появился новый внешний код;
- `changed` — изменились адрес, координаты, формат или способы обслуживания;
- `unchanged` — карточка не изменилась;
- `not_observed` — прежний код не найден в новом снимке;
- `inactive` — сеть прямо сообщила о неактивности либо отсутствие подтверждено
  повторной проверкой.

`not_observed` не означает автоматическое закрытие магазина. Особенно это
важно для Пятёрочки: магазин мог временно исчезнуть из результатов из-за зоны
доставки или неполного покрытия точками. Исходный код и вся история должны
сохраняться.

Будущий интерфейс должен запускать это как отдельную операцию «Обновить
справочник магазинов», показывать изменения до применения и только после
подтверждения передавать актуальные коды планировщику товарного сбора.

## Проверки перед реальным запуском

```powershell
$env:CI='true'
pnpm lint
pnpm typecheck
pnpm test
```

Не следует одновременно запускать два процесса с одним браузерным профилем.
Для каждой сети используется только её отдельный профиль. Скрипт не управляет
VPN, не обходит CAPTCHA и не увеличивает параллельность запросов.

## Разбиение по районам

Если есть GeoJSON `FeatureCollection` с полигонами районов и названием в поле
`name`, `district` или `title`, районы назначаются локально по координатам:

```powershell
pnpm discover:stores -- --chain magnit --city "Санкт-Петербург" --query "санкт-петербург," --districts "data/input/spb-districts.geojson"
```

Муниципальные границы можно передать отдельно через
`--municipal-districts`. Без этих файлов коды, адреса и координаты сохраняются,
а поля районов остаются `null`.
