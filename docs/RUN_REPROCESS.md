# Повторная обработка JSON до подключения PostgreSQL

Нормализаторы обеих сетей уже преобразуют исходные ответы в общие снимки
товаров. Этот инструмент запускает те же нормализаторы на сохранённом архиве.
SQL-запросов, транзакций и импортера в PostgreSQL пока нет.

В меню появился пункт 10. Через терминал:

```powershell
node --import tsx src/reprocess.ts --raw "data/raw/ДАТА/СЕТЬ/КАТАЛОГ_СБОРА"
```

По умолчанию выполняется только проверка и пересчёт в памяти. Для записи
нового файла добавьте `--write`. Также есть `pnpm run reprocess -- ...`.

## Входные данные

Поддерживается завершённый raw-каталог нашего сборщика:

- manifest.json с сетью, магазином, категорией, временем и списком страниц;
- все указанные page-....json;
- соответствующие page-....json.meta.json с точным временем получения.

Старые массивы из DevTools без manifest/метаданных не поддержаны этой командой:
нельзя достоверно придумать отсутствующее время сбора. Неполный архив не
выдаётся за завершённый. Проверяются имена и порядок страниц, offset,
количества, пагинация Магнита, метаданные и результат нормализации.
Дубликаты товаров и другие структурные ошибки блокируют запись.

## Время и восстановленные очереди

По умолчанию runStartedAt берётся из raw manifest, часовой пояс —
Europe/Moscow (можно явно задать `--time-zone`). collectedAt всегда берётся
из сохранённых метаданных страниц, не из текущего времени обработки.

У Магнита после resume логическая дата может относиться к началу очереди,
а raw manifest — к более поздней попытке конкретной категории. Для точного
сохранения даты исходной очереди передайте соответствующий файл состояния:

```powershell
node --import tsx src/reprocess.ts --raw "data/raw/ДАТА/magnit/КАТАЛОГ" --state "data/state/magnit/RUN.json" --write
```

Проверяется совпадение raw-каталога, магазина и категории со состоянием.
Часовой пояс и дата очереди берутся из состояния. Если старый raw-путь уже
не указан в нём после повторной попытки, такой state будет отклонён.
Для Пятёрочки используется время manifest, как в её текущем нормализаторе.

## Результат и дальнейшая БД

Новый файл появляется в data/normalized/ДАТА/СЕТЬ с суффиксом
`-reprocessed-UUID.json`. Предыдущие версии и raw не удаляются и не заменяются.
Поле provenance содержит ссылку на manifest, SHA-256 входного комплекта,
исходное время, часовой пояс и время повторной обработки. Метаданные магазина
и категории присутствуют и у пустого результата. schemaVersion равен 1.

SHA-256 помогает определить одинаковые исходники, но сам по себе НЕ является
реализованной защитой от повторного импорта в БД. При подключении PostgreSQL
ещё нужны таблицы, миграции, транзакции и согласованный ключ идемпотентности.
Также нужно выбрать, какая версия нормализации активна для анализа.
Все файлы нельзя бездумно складывать как независимые наблюдения.

Команда не запускает браузер, не меняет состояние очереди, не обновляет
старые файлы и не удаляет исходники. Без --write не создаёт новых файлов.
