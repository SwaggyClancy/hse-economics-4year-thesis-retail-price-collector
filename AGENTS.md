# Инструкции для Codex

## Общие правила

- Перед изменениями прочитать `docs/PROJECT_CONTEXT.md`.
- Не менять архитектуру крупными блоками без объяснения причины.
- Использовать TypeScript.
- Разделять Пятёрочку и Магнит на независимые модули.
- Не создавать один огромный файл.
- Не хранить секреты, cookies, пароли и строки подключения в Git.
- Не удалять исходные JSON после обработки.
- После значимых изменений запускать:
  - lint;
  - typecheck;
  - tests.
- Не увеличивать параллельность запросов без отдельного решения.
- Не добавлять обход CAPTCHA и других средств контроля доступа.
- Уважать ограничения сайтов и использовать осторожную частоту запросов.

## Стиль кода

- Предпочитать маленькие функции с понятными именами.
- Явно типизировать входные и выходные данные.
- Ошибки не скрывать.
- Все сетевые ошибки записывать в журнал.
- Повторные попытки делать с увеличивающейся паузой.
- Для времени хранить точный timestamp.
- Для денежных значений использовать понятную и единую модель.
- Код сети не должен напрямую зависеть от PostgreSQL.

## Архитектурные границы

```text
collector
  получает данные конкретной сети

normalizer
  преобразует ответ сети в общую модель

repository
  сохраняет данные

scheduler
  создаёт и запускает задачи

exporter
  формирует выгрузки

api
  показывает статус и принимает команды
```

## Правила работы с браузером

- Использовать отдельный профиль для каждой сети.
- Не использовать основной пользовательский профиль Chrome.
- Профили хранить локально в `profiles/`.
- Запросы по возможности выполнять внутри контекста открытой страницы.
- Не логировать cookies и чувствительные заголовки.
- Поддерживать видимый и headless-режим через конфигурацию.

## Правила хранения данных

- Исходные ответы сохранять в `data/raw/`.
- Нормализованные локальные файлы сохранять в `data/normalized/`.
- Все ошибки писать в `logs/`.
- Не коммитить реальные данные, браузерные профили и `.env`.

## Порядок реализации

1. Одна сеть, один магазин, одна категория.
2. Полная пагинация.
3. Исходный JSON.
4. Нормализация.
5. PostgreSQL.
6. Вторая сеть.
7. Очередь задач.
8. Повторы и восстановление.
9. Ограниченная параллельность.
10. Расписание.
11. API и интерфейс.
12. Экспорт.
